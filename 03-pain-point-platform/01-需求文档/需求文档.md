# 痛点方案撮合平台 - 需求文档

## 一、项目概述

### 1.1 产品定位
一个连接"痛点发布者"与"解决方案提供者"的撮合平台，通过 AI 标准化、投票筛选，降低信息匹配成本，提升问题解决效率。

### 1.2 核心价值主张
- **对痛点发布者**：免费发布困惑，获得高质量解决方案
- **对方案提供者**：发现真实需求，展示专业能力，获得认可/收益
- **对社会**：减少信息摩擦，加速知识流动

### 1.3 目标用户

| 用户类型 | 核心需求 | 使用场景 |
|---------|---------|---------|
| 个人用户 | 解决生活/工作中的困惑 | 租房被坑、求职迷茫、选品纠结 |
| 企业用户 | 获取真实用户痛点 | 产品迭代、服务优化 |
| 专业人才 | 建立个人品牌/接单 | 咨询师、设计师、技术专家 |

### 1.4 竞品分析

| 产品 | 定位 | 优点 | 不足 |
|-----|------|-----|------|
| 知乎 | 问答社区 | 用户量大、优质内容多 | 门槛高、噪音多 |
| 小红书 | 生活分享 | 内容丰富、互动强 | 碎片化、搜索弱 |
| Product Hunt | 产品投票 | 投票机制清晰 | 仅限产品 |
| 声网/白板 | 实时协作 | 交互强 | 非异步、非公开 |

**我们的机会**：
- 专注"痛点-方案"闭环
- AI 标准化降低发布门槛
- 投票机制保证质量

## 二、功能需求

### 2.1 用户系统

#### 2.1.1 注册登录
- [ ] 手机号 + 验证码登录
- [ ] 第三方登录（微信、Google、GitHub）
- [ ] 游客模式（可浏览，不能发布/投票）

#### 2.1.2 用户Profile
- [ ] 头像、昵称、个人简介
- [ ] 擅长领域/标签（可多选）
- [ ] 历史发布统计（痛点数、方案数、获赞数）
- [ ] 认证体系（可选：实名认证、专业认证）

### 2.2 痛点模块

#### 2.2.1 发布痛点
**表单字段**：

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|-----|------|
| 痛点标题 | 文本 | 是 | 50字以内，简洁有力 |
| 详细描述 | 富文本 | 是 | 支持Markdown、图片 |
| 痛点类型 | 单选 | 是 | 生活/工作/技术/情感/其他 |
| 期望解决时间 | 单选 | 是 | 紧急/近期/长期 |
| 预算范围 | 单选 | 否 | 无/有预算（如选有，填金额） |
| 标签 | 多选 | 否 | 自定义或系统推荐 |

**AI 增强功能**：
- [ ] 自动提取关键词、生成标签建议
- [ ] 自动分类到对应领域
- [ ] 生成结构化摘要（AI 整理后展示）
- [ ] 语法检查、敏感词过滤

#### 2.2.2 痛点列表
- [ ] 瀑布流/列表切换
- [ ] 筛选：类型、时间、状态（待解决/已解决）
- [ ] 排序：最新/最热/投票数
- [ ] 搜索：关键词、标签、用户

#### 2.2.3 痛点详情
- [ ] 原始描述 + AI 整理版本并排展示
- [ ] 痛点元数据（发布时间、浏览量、标签）
- [ ] 相关痛点推荐
- [ ] 分享功能（链接/海报）

### 2.3 方案模块

#### 2.3.1 发布方案
**表单字段**：

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|-----|------|
| 关联痛点 | 关联 | 是 | 选择要响应的痛点 |
| 方案标题 | 文本 | 是 | 30字以内 |
| 方案内容 | 富文本 | 是 | 支持Markdown、图片、代码块 |
| 方案类型 | 单选 | 是 | 完整方案/思路分享/工具推荐 |
| 预计成本 | 单选 | 否 | 免费/低/中/高 |
| 实施难度 | 单选 | 否 | 简单/中等/困难 |

**限制**：
- 每个痛点最多 N 个方案（防止刷屏）
- 发布前需确认"我试过/研究过这个方案"

#### 2.3.2 方案展示
- [ ] 方案列表（按投票排序）

#### 2.4.2 排行榜

## 五、技术架构

### 5.1 技术选型（建议）

| 层级 | 技术 | 理由 |
|-----|------|-----|
| 前端 | Next.js + TailwindCSS | SSR好、开发快 |
| 移动端 | React Native 或 Flutter | 一套代码双端 |
| 后端 | Node.js (NestJS) 或 Python (FastAPI) | AI集成方便 |
| 数据库 | PostgreSQL + Redis | 结构化+缓存 |
| 对象存储 | 阿里云 OSS / AWS S3 | 图片存储 |
| AI服务 | OpenAI API / Claude API | 文本处理 |
| 部署 | Vercel / 阿里云 | 简单易用 |

  id, phone, email, avatar, nickname, bio,

  id, user_id, title, raw_content, ai_summary,

## 九、MVP 功能优先级与实施计划

### 9.1 MVP 核心目标
验证"痛点-方案"撮合模式，验证用户是否愿意发布痛点、是否有方案提供者愿意响应、投票机制是否有效。

### 9.2 MVP vs 完整版对比

| 维度 | MVP | 完整版 |
|-----|-----|--------|
| 形态 | 网页（Web） | 网页 + App |
| 用户 | 基础注册登录 | 第三方登录、认证体系 |
| 痛点 | 发布 + AI整理 | + 匿名发布、分享 |
| 方案 | 基础发布 | + 追问、对比 |
| 投票 | 顶/踩 | + 打赏、排行榜 |
| 互动 | 无 | 评论、通知、收藏 |

### 9.3 MVP 功能优先级

#### 🔥 P0 - 核心闭环（必须做）

| 功能模块 | 具体功能 | 描述 | 预估工时 |
|---------|---------|------|---------|
| **用户系统** | 注册登录 | 手机号+验证码登录，游客可浏览 | 2-3天 |
| **痛点模块** | 发布痛点 | 标题、描述、类型、标签，AI自动整理摘要 | 3-4天 |
| **方案模块** | 发布方案 | 关联痛点、方案内容 | 2-3天 |
| **投票系统** | 顶/踩功能 | 每个用户每条限投1次 | 1-2天 |
| **痛点模块** | 列表浏览 | 瀑布流、筛选（类型/时间）、搜索 | 2天 |
| **痛点模块** | 痛点详情 | 原始描述 + AI整理对比展示 | 1天 |

**MVP 最小闭环**：用户能发痛点 → 别人能看到 → 别人能回方案 → 大家能投票

#### ⭐ P1 - 增强体验（应该做）

| 功能模块 | 具体功能 | 描述 | 预估工时 |
|---------|---------|------|---------|
| **用户系统** | 个人主页 | 头像、昵称、历史发布统计 | 1天 |
| **互动功能** | 评论/追问 | 二级评论、@提及 | 2-3天 |
| **通知系统** | 基础通知 | 方案提醒、投票提醒 | 2天 |
| **投票系统** | 收藏功能 | 收藏感兴趣的痛点/方案 | 0.5天 |

#### 🎯 P2 - 锦上添花（后期再加）

| 功能模块 | 具体功能 | 描述 |
|---------|---------|------|
| **投票系统** | 打赏功能 | 付费感谢优质方案 |
| **投票系统** | 排行榜 | 日/周/月 Top 痛点、方案 |
| **分享功能** | 分享海报 | 生成海报分享到社交媒体 |
| **痛点模块** | 匿名发布 | 保护发布者隐私 |
| **互动功能** | 方案追问 | 针对方案的具体问题 |

### 9.4 技术选型决策

#### 形态选择
- **MVP**：做网页（Web）✅
- **后期**：根据用户留存情况，决定是否做 App（React Native / Flutter）

**决策理由**：
1. Next.js 本身就是 Web 框架，天然支持
2. 网页发版快（秒级），App 发版需要审核（周级）
3. MVP 阶段验证产品价值最重要，不需要双端投入
4. 技术栈统一，无需同时维护两套代码

**后期扩展路径**：网页验证 → 核心用户留存 → React Native/Flutter 做 App

#### 推荐技术栈

| 层级 | 技术选型 | 理由 |
|-----|---------|------|
| 前端框架 | **Next.js 15** | SSR 好、生态成熟、部署简单 |
| UI 组件库 | **Shadcn/ui + TailwindCSS** | 现代、轻量、易定制 |
| 后端框架 | **Next.js API Routes** 或 NestJS | MVP 阶段用 Next.js 自带后端足够 |
| 数据库 | **PostgreSQL** + **Prisma** | 结构化数据强、ORM 方便 |
| 身份认证 | **NextAuth.js** | 开箱即用、支持多种 Provider |
| AI 集成 | **DeepSeek API (DeepSeek Chat)** | 效果好、价格低（约为 GPT-4o 的 1/10） |
| 图片存储 | **Vercel Blob** 或 AWS S3 | 简单集成 |
| 部署平台 | **Vercel** | Next.js 官方支持、免费额度够用 |

### 9.9 需求描述（给 AI 开发）

**项目名称**：痛点方案撮合平台（Web MVP）

**项目目标**：验证"痛点发布 - AI整理 - 方案响应 - 投票筛选"闭环模式

**核心用户故事**：
1. 作为用户，我可以通过手机号注册登录
2. 作为用户，我可以发布痛点（标题、描述、类型、标签），AI 自动整理摘要
3. 作为用户，我可以浏览痛点列表，按类型筛选、关键词搜索
4. 作为用户，我可以点击痛点查看详情，看到 AI 整理后的摘要
5. 作为用户，我可以针对痛点发布解决方案
6. 作为用户，我可以给痛点/方案投票（顶/踩）
7. 作为用户，我可以收藏感兴趣的痛点/方案
8. 作为用户，我可以查看自己的个人主页，看到历史发布统计

**技术要求**：
- Next.js 15 + TailwindCSS + Shadcn/ui
- PostgreSQL + Prisma
- NextAuth.js 身份认证
- **DeepSeek API (DeepSeek Chat)** 做 AI 整理
- Vercel 部署

**约束条件**：
- MVP 只做 Web，不需要 App
- 不需要匿名发布
- 不需要打赏/付费功能
- 不需要排行榜（P2 做）
- 每个用户每条只能投一次票（防刷）

**验收标准**：
- 用户能完成注册登录（1分钟内）
- 痛点发布后 3 秒内 AI 生成摘要
- 页面加载时间 < 3 秒
- 支持 100+ 并发用户
