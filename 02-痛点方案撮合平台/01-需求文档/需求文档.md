# 痛点方案撮合平台 - 需求文档

## 一、项目概述

### 1.1 产品定位
一个连接"痛点发布者"与"解决方案提供者"的撮合平台，通过 AI 标准化、投票筛选，降低信息匹配成本，提升问题解决效率。

### 1.2 核心价值主张
- **对痛点发布者**：免费发布困惑，获得高质量解决方案
- **对方案提供者**：发现真实需求，展示专业能力，获得认可/收益
- **对社会**：减少信息摩擦，加速知识流动

### 1.3 目标用户

| 用户类型 | 核心需求 | 使用场景 |
|---------|---------|---------|
| 个人用户 | 解决生活/工作中的困惑 | 租房被坑、求职迷茫、选品纠结 |
| 企业用户 | 获取真实用户痛点 | 产品迭代、服务优化 |
| 专业人才 | 建立个人品牌/接单 | 咨询师、设计师、技术专家 |

### 1.4 竞品分析

| 产品 | 定位 | 优点 | 不足 |
|-----|------|-----|------|
| 知乎 | 问答社区 | 用户量大、优质内容多 | 门槛高、噪音多 |
| 小红书 | 生活分享 | 内容丰富、互动强 | 碎片化、搜索弱 |
| Product Hunt | 产品投票 | 投票机制清晰 | 仅限产品 |
| 声网/白板 | 实时协作 | 交互强 | 非异步、非公开 |

**我们的机会**：
- 专注"痛点-方案"闭环
- AI 标准化降低发布门槛
- 投票机制保证质量

## 二、功能需求

### 2.1 用户系统

#### 2.1.1 注册登录
- [ ] 手机号 + 验证码登录
- [ ] 第三方登录（微信、Google、GitHub）
- [ ] 游客模式（可浏览，不能发布/投票）

#### 2.1.2 用户Profile
- [ ] 头像、昵称、个人简介
- [ ] 擅长领域/标签（可多选）
- [ ] 历史发布统计（痛点数、方案数、获赞数）
- [ ] 认证体系（可选：实名认证、专业认证）

### 2.2 痛点模块

#### 2.2.1 发布痛点
**表单字段**：

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|-----|------|
| 痛点标题 | 文本 | 是 | 50字以内，简洁有力 |
| 详细描述 | 富文本 | 是 | 支持Markdown、图片 |
| 痛点类型 | 单选 | 是 | 生活/工作/技术/情感/其他 |
| 期望解决时间 | 单选 | 是 | 紧急/近期/长期 |
| 预算范围 | 单选 | 否 | 无/有预算（如选有，填金额） |
| 标签 | 多选 | 否 | 自定义或系统推荐 |

**AI 增强功能**：
- [ ] 自动提取关键词、生成标签建议
- [ ] 自动分类到对应领域
- [ ] 生成结构化摘要（AI 整理后展示）
- [ ] 语法检查、敏感词过滤

#### 2.2.2 痛点列表
- [ ] 瀑布流/列表切换
- [ ] 筛选：类型、时间、状态（待解决/已解决）
- [ ] 排序：最新/最热/投票数
- [ ] 搜索：关键词、标签、用户

#### 2.2.3 痛点详情
- [ ] 原始描述 + AI 整理版本并排展示
- [ ] 痛点元数据（发布时间、浏览量、标签）
- [ ] 相关痛点推荐
- [ ] 分享功能（链接/海报）

### 2.3 方案模块

#### 2.3.1 发布方案
**表单字段**：

| 字段名 | 类型 | 必填 | 说明 |
|-------|------|-----|------|
| 关联痛点 | 关联 | 是 | 选择要响应的痛点 |
| 方案标题 | 文本 | 是 | 30字以内 |
| 方案内容 | 富文本 | 是 | 支持Markdown、图片、代码块 |
| 方案类型 | 单选 | 是 | 完整方案/思路分享/工具推荐 |
| 预计成本 | 单选 | 否 | 免费/低/中/高 |
| 实施难度 | 单选 | 否 | 简单/中等/困难 |

**限制**：
- 每个痛点最多 N 个方案（防止刷屏）
- 发布前需确认"我试过/研究过这个方案"

#### 2.3.2 方案展示
- [ ] 方案列表（按投票排序）
- [ ] 方案详情（支持评论/追问）
- [ ] "我是TA"：方案提供者匿名展示（可选）
- [ ] 方案对比视图（多方案并排）

### 2.4 投票系统

#### 2.4.1 投票机制
**痛点投票**：
- [ ] "我也遇到这个问题" 👍
- [ ] "这个痛点不成立" 👎

**方案投票**：
- [ ] "有用/没帮助" 👍/👎
- [ ] "收藏" ⭐
- [ ] "打赏" 💰（可选）

**防刷机制**：
- [ ] 登录才能投票
- [ ] 每个用户每条只能投一次
- [ ] IP/设备风控

#### 2.4.2 排行榜
- [ ] 今日/周/月 Top 痛点
- [ ] 今日/周/月 Top 方案
- [ ] 优质贡献者榜

### 2.5 互动功能

#### 2.5.1 评论/追问
- [ ] 二级评论（盖楼）
- [ ] @提及用户
- [ ] 方案下追问"具体怎么做？"

#### 2.5.2 通知系统
- [ ] 有人发布方案（痛点发布者）
- [ ] 有人投票（方案提供者）
- [ ] 有人评论/追问
- [ ] 系统通知（点赞/收藏/获奖）

### 2.6 AI 功能

#### 2.6.1 痛点整理
```
输入：用户原始痛点文本
输出：
{
  "summary": "一句话总结痛点",
  "tags": ["标签1", "标签2", "标签3"],
  "category": "技术类-前端开发",
  "urgency": "中",
  "suggested_budget": "500-1000元"
}
```

#### 2.6.2 方案优化（可选）
- [ ] 语法润色
- [ ] 结构化重组
- [ ] 补充执行步骤

#### 2.6.3 智能推荐（可选）
- [ ] 根据用户标签推荐相关痛点
- [ ] 相似痛点聚合

## 三、非功能需求

### 3.1 性能需求
- 页面加载时间 < 3秒（LCP）
- API 响应时间 < 500ms（P95）
- 支持同时在线用户 1000+（MVP阶段）

### 3.2 安全需求
- [ ] HTTPS 加密传输
- [ ] XSS/CSRF 防护
- [ ] SQL 注入防护
- [ ] 敏感词过滤（痛点/方案/评论）
- [ ] 隐私保护（可选：匿名发布）

### 3.3 合规需求
- [ ] 用户数据隐私政策
- [ ] 用户协议
- [ ] AI 生成内容声明

### 3.4 可用性
- [ ] 移动端适配（响应式）
- [ ] PWA 支持（可选）
- [ ] 多语言支持（后期）

## 四、运营策略（冷启动）

### 4.1 种子用户获取
1. **定向邀请**：你的团队/朋友（10-20人）
2. **垂直社区**：V2EX、即刻、PMCaff
3. **KOL合作**：找几个有影响力的博主内测

### 4.2 内容冷启动
- [ ] 发布 20-50 个真实痛点（团队模拟真实用户）
- [ ] 每个痛点配 2-3 个方案
- [ ] 确保内容质量，宁缺毋滥

### 4.3 激励方案
- [ ] 早期用户专属徽章
- [ ] 优质贡献者免审核
- [ ] 投票排名奖励（可选：实物/积分）

## 五、技术架构

### 5.1 技术选型（建议）

| 层级 | 技术 | 理由 |
|-----|------|-----|
| 前端 | Next.js + TailwindCSS | SSR好、开发快 |
| 移动端 | React Native 或 Flutter | 一套代码双端 |
| 后端 | Node.js (NestJS) 或 Python (FastAPI) | AI集成方便 |
| 数据库 | PostgreSQL + Redis | 结构化+缓存 |
| 对象存储 | 阿里云 OSS / AWS S3 | 图片存储 |
| AI服务 | OpenAI API / Claude API | 文本处理 |
| 部署 | Vercel / 阿里云 | 简单易用 |

### 5.2 数据模型（核心表）

```sql
-- 用户表
users (
  id, phone, email, avatar, nickname, bio, 
  tags[], reputation_score, created_at
)

-- 痛点表
pain_points (
  id, user_id, title, raw_content, ai_summary,
  category, tags[], urgency, budget_range,
  status, view_count, vote_count, created_at
)

-- 方案表
solutions (
  id, pain_point_id, user_id, title, content,
  solution_type, difficulty, cost, vote_count, 
  status, created_at
)

-- 投票表
votes (
  id, user_id, target_type, target_id, vote_type, created_at
)

-- 评论表
comments (
  id, user_id, target_type, target_id, parent_id, content, created_at
)
```

### 5.3 API 设计（RESTful）

| 方法 | 端点 | 说明 |
|-----|------|-----|
| POST | /api/pain-points | 发布痛点 |
| GET | /api/pain-points | 痛点列表 |
| GET | /api/pain-points/:id | 痛点详情 |
| POST | /api/solutions | 发布方案 |
| POST | /api/votes | 投票 |
| POST | /api/ai/summarize | AI整理痛点 |

## 七、风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|-----|-------|------|---------|
| 冷启动难 | 高 | 平台无内容 | 定向邀请、种子内容 |
| 内容质量低 | 中 | 用户流失 | AI过滤、人工审核、投票机制 |
| 刷票/垃圾信息 | 中 | 体验下降 | 风控、IP限制、验证码 |
| 资金不足 | 低 | 项目停滞 | MVP验证后再融资 |
